# 家庭多人搬家协作设计

日期：2026-08-13  
状态：已确认，待实施计划

## 1. 背景

搬家通常由 1–3 名家人共同完成。有人在旧家整理和装箱，有人负责运输，有人在新家接收和安置。现有 App 是设备本地优先的单人台账，任务、房间、箱子、物品和照片均保存在当前设备，不能回答以下协作问题：

- 当前由谁处理哪个任务或箱子；
- 某个状态是谁、何时更新的；
- 多台设备同时或离线修改时应保留哪次变化；
- 其他家人如何低门槛加入同一次搬家；
- 照片如何在成员之间安全共享。

本设计将 App 从单机台账扩展为家庭成员共同维护的搬家项目。所有成员拥有同等编辑权限，不支持搬家公司或临时访客角色。

## 2. 产品目标

核心目标是让 1–3 名家人在网络不稳定的搬家现场保持同一份可信进度，减少重复劳动和口头确认。

第一版成功标准：

- 三台设备可以通过邀请链接加入同一个搬家项目；
- 任一成员可以认领、指派和修改任务、箱子与物品；
- 设备断网时仍能新增记录、改变状态和添加照片；
- 恢复网络后自动合并，并让其他设备获取全部变化；
- 同时创建箱子不会产生重复内部 ID 或正式箱号；
- 匿名成员升级 Apple 登录后，项目关系和操作历史保持不变；
- 非项目成员无法访问项目数据和照片；
- 软删除内容可在 30 天内恢复。

## 3. 已确认的产品原则

1. 所有家人拥有相同编辑权限。
2. 邀请链接优先降低加入门槛，首次加入不强制注册。
3. 系统为每位成员创建独立匿名身份，成员需要填写称呼。
4. 后续使用 Apple 登录将匿名身份升级为可恢复的正式身份。
5. 离线操作必须立即在本机生效，联网后自动同步。
6. 任务、箱子、物品、房间和照片都进入共享范围。
7. 关键变化即时推送，普通编辑只进入活动记录。
8. 可以认领或指派负责人，但负责人允许为空，且不限制其他成员编辑。
9. 普通字段最后一次有效修改生效；箱子进度默认只前进不倒退。
10. 删除采用软删除和 30 天回收站。
11. 数据模型支持多个项目，但第一版界面只呈现一个活跃项目。
12. 项目完成后归档并默认只读，任一成员可重新开启。

## 4. 技术路线选择

采用 Supabase 托管后端：

- Supabase Auth：匿名身份、Apple 登录和身份链接；
- Postgres：项目、成员及领域实体；
- Realtime：在线设备的变更提示；
- Supabase Storage：成员可见的私有照片；
- Row Level Security：按项目成员关系控制数据和照片访问；
- Edge Functions 或数据库函数：接受邀请、分配箱号、执行受保护的事务与推送任务。

开发和 TestFlight 内测使用 Supabase Free。正式发布前根据活跃用户、照片容量、流量、免费项目暂停风险和备份需求重新评估 Pro，不在内测阶段提前升级。

不选择整份 `MovingState` 云端覆盖，也不选择设备间点对点同步。云端按实体保存，本地按操作同步，以避免一台设备覆盖其他成员的全部变化。

## 5. 核心用户流程

### 5.1 创建共享项目

1. App 首次启动时创建匿名 Supabase 用户。
2. 用户填写自己的家庭称呼。
3. 创建搬家项目并成为第一位成员。
4. 如果设备已有现有本地数据，明确提示将本地任务、房间、箱子、物品和照片迁移到新项目。
5. 迁移过程使用稳定 UUID，并保留现有展示内容。

迁移失败时不删除原本地数据。只有云端确认成功并完成一次回读后，才将共享项目设为当前项目。

### 5.2 邀请家人

1. 首页项目标题旁显示成员入口。
2. 任一成员可以生成默认 7 天有效的邀请链接。
3. 通过系统分享面板发送 HTTPS 链接。
4. 链接可随时撤销并重新生成。
5. 邀请 token 只用于建立成员关系，加入完成后不能继续作为访问凭证。

邀请使用 iOS Universal Links：已安装 App 时直接进入加入页；未安装时显示轻量落地页，并保存邀请信息以便安装后继续。

### 5.3 加入项目

1. 接收者打开邀请链接。
2. App 在本机创建或恢复匿名身份。
3. 用户填写称呼，例如“妈妈”。
4. 服务端校验邀请有效期、撤销状态和项目状态。
5. 创建 `project_members` 关系。
6. 拉取项目快照与当前同步游标，进入首页。

同一用户重复打开链接不得创建重复成员关系。

### 5.4 升级 Apple 登录

首次成功上传照片后提示用户保护记录，但允许跳过。设置页持续提供“使用 Apple 登录保护搬家记录”。

升级通过身份链接完成，保留 Supabase 用户 ID，从而保持成员关系、负责人字段和活动记录不变。若 Apple 身份已经对应其他账号，必须进入明确的账户合并流程，不可静默覆盖任何项目关系。

## 6. 协作体验

### 6.1 首页

新增：

- 项目名称及成员入口；
- “我的任务”和“待认领”摘要；
- 最近关键活动；
- 仅在异常时出现的同步提示，如“3 项待同步”或“同步失败”。

正常在线同步不显示持续性横幅，避免干扰搬家操作。

### 6.2 箱子

每个箱子显示：

- 唯一展示箱号；
- 可选负责人；
- 最近修改人和时间；
- 当前同步异常状态；
- 搬家当天可直接点击的下一步状态。

状态保持现有顺序：

`待整理 → 已装箱 → 已搬走 → 已到达 → 已拆箱`

普通操作不能自动回退。需要纠正时使用“更正状态”，填写可选原因并生成活动记录。

### 6.3 任务

增加负责人，以及“我的 / 待认领 / 全部”筛选。任务完成时记录完成者和完成时间，但所有成员都可以再次打开或编辑。

### 6.4 活动记录

保留最近 30 天的关键事件：

- 成员加入；
- 创建、删除、恢复重要实体；
- 箱子状态变化；
- 任务完成；
- 照片上传；
- 项目归档和重新开启；
- 需要人工处理的冲突。

活动记录只读，不承担聊天功能。普通备注文字的每次编辑无需形成冗长事件，只保留实体最后修改人和时间。

## 7. 云端数据模型

### 7.1 身份与项目

- `profiles`
  - `user_id`
  - `display_name`
  - `created_at`
  - `updated_at`
- `moving_projects`
  - `id`
  - `name`
  - `moving_date`
  - `status`: `active | archived`
  - `created_by`
  - `created_at`
  - `updated_at`
- `project_members`
  - `project_id`
  - `user_id`
  - `joined_at`
  - 唯一约束：`(project_id, user_id)`
- `invitations`
  - `id`
  - `project_id`
  - `token_hash`
  - `expires_at`
  - `revoked_at`
  - `created_by`
  - `created_at`

所有成员权限相同，因此第一版不增加 `role` 字段。若未来出现管理员需求，再通过迁移增加，避免提前制造无用权限分支。

### 7.2 领域实体

- `rooms`
- `moving_tasks`
- `moving_boxes`
- `moving_items`
- `photos`
- `activity_events`

`rooms` 表示搬家箱子的旧家/新家房间。（原“家中记忆”功能已于 2026-08-15 从产品中移除，其数据不再纳入同步范围。）

所有可编辑实体至少包含：

```ts
type SyncableEntity = {
  id: string;
  projectId: string;
  assigneeId: string | null;
  createdBy: string;
  updatedBy: string;
  createdAt: string;
  updatedAt: string;
  version: number;
  deletedAt: string | null;
};
```

只有任务和箱子第一版需要 `assigneeId`；其他实体可不包含该字段。字段以实际表结构为准，不为追求统一而增加无意义列。

`moving_boxes` 的内部 UUID 与展示箱号分离：

- 客户端离线创建时立即生成 UUID；
- 本地暂时显示“待编号”；
- 服务端在事务中按项目分配唯一连续号码；
- 同步成功后展示正式 `BOX-012`。

### 7.3 操作与游标

- `applied_operations`
  - `operation_id`
  - `project_id`
  - `actor_id`
  - `applied_at`
- `project_changes`
  - 项目内单调递增游标；
  - 实体类型、实体 ID、变更类型和版本；
  - 用于断线后的可靠增量拉取。

`applied_operations` 为客户端重试提供幂等性。`project_changes` 是可靠恢复机制，Realtime 只是降低在线延迟，不能替代游标同步。

## 8. 本地数据架构

现有 `AsyncStorage` 整体 JSON 模型保留为迁移来源，但协作版不再把它作为主数据库。实现时选择与 React Native 0.81 兼容、支持事务和索引的 SQLite 方案，并先核对官方集成文档及 iOS 构建兼容性。

本地至少包含：

- 当前项目的实体表；
- `outbox_operations`；
- `sync_state`，保存每个项目的最后游标；
- 照片本地缓存与上传状态；
- 当前用户会话，敏感 token 进入 iOS Keychain，而不是普通 AsyncStorage。

## 9. 离线同步协议

### 9.1 本地写入

每次用户操作：

1. 在本地事务中修改实体；
2. 生成唯一 `operationId`；
3. 写入 `outbox_operations`；
4. 立即刷新界面；
5. 网络可用时提交队列。

### 9.2 服务端提交

服务端在事务中：

1. 校验当前用户属于项目；
2. 检查 `operationId` 是否已经处理；
3. 校验基础版本和业务规则；
4. 应用变更；
5. 记录活动事件和项目变化游标；
6. 记录已处理操作；
7. 返回最新实体和游标。

重复提交相同操作必须返回首次成功结果，不得重复创建实体、活动事件或箱号。

### 9.3 获取远端变化

客户端在以下时机携带最后游标拉取增量：

- App 启动；
- 回到前台；
- 网络恢复；
- Realtime 收到项目变化提示；
- 定期兜底同步。

先提交本地 outbox，再拉取远端增量；如果提交依赖远端新版本，服务端返回结构化冲突，客户端合并后生成新的操作。

### 9.4 同步状态

实体状态为：

- `synced`
- `pending`
- `failed`
- `needs_attention`

正常状态不显式展示。顶部只在存在未解决状态时汇总，单个实体可查看失败原因并重试。

## 10. 冲突规则

- 名称、备注、位置和负责人：最后一次服务端接受的修改生效。
- 箱子状态：取状态序列中更靠后的状态，普通修改不得回退。
- 更正箱子状态：作为显式操作，允许回退并记录操作者和原因。
- 任务完成：以最后一次有效操作为准，同时记录完成者和完成时间。
- 删除：使用 `deletedAt` 软删除；删除与编辑冲突时保留删除状态，但恢复后保留最后编辑内容。
- 不同照片：合并保留。
- 同一照片标题：最后修改生效。
- 无法自动合并的结构性冲突：进入 `needs_attention`，不阻塞其他实体同步。

## 11. 照片同步

1. 拍摄或选取后先复制到 App 本地目录。
2. 客户端生成缩略图和适合移动端查看的压缩共享版本。
3. 照片元数据与上传任务写入本地事务。
4. 在线时上传私有 Storage bucket。
5. 服务端路径使用项目 ID 和照片 UUID，不包含用户填写的名称。
6. 其他成员先加载缩略图，打开详情时按需加载共享高清版本。
7. 上传失败只影响该照片，不阻断关联箱子或房间的文字状态。
8. 删除先软删除元数据，文件在回收期限后异步清理。

不默认上传相机原始文件，也不依赖 Supabase 收费图片转换。压缩和缩略图在设备端完成，以控制 Free 阶段存储和流量。

## 12. 权限与安全

- 所有客户端使用公开 publishable key，不包含 service role secret；
- 所有暴露表启用 RLS；
- 读写策略要求 `auth.uid()` 是该记录 `project_id` 的有效成员；
- Storage 读写策略从对象路径提取项目 ID，并验证成员关系；
- 接受邀请、生成邀请和项目级危险操作通过受保护的数据库函数或 Edge Function 完成；
- 邀请 token 使用高熵随机值，数据库只保存哈希；
- 匿名注册启用平台支持的限流和防滥用措施；
- 整个项目删除或清空需要二次确认；
- 任何客户端不可绕过软删除保留期直接清理共享照片。

## 13. 推送通知

即时推送：

- 有人指派任务给当前成员；
- 搬家当天箱子进入“已搬走”或“已到达”；
- 新成员加入项目；
- 出现需要人工确认的同步冲突。

不推送：

- 修改备注或名称；
- 普通照片上传；
- 当前用户自己的操作。

同一项目短时间内的多条通知合并。推送失败不能影响数据写入；通知任务异步执行，并记录失败以便重试。

## 14. 删除、归档与恢复

- 任务、箱子、物品和照片软删除 30 天；
- 回收站显示删除人、删除时间和剩余保留时间；
- 恢复后重新参与正常同步；
- 项目完成后设为 `archived`，默认只读；
- 任一成员可以重新开启；
- 数据模型支持多个项目，第一版仅选择一个当前项目进入主界面。

## 15. Free 阶段成本护栏

- 开发与 TestFlight 内测使用一个 Supabase Free 项目；
- 不为每个搬家创建 Supabase 项目，搬家只是数据库中的 `moving_projects` 记录；
- 客户端生成缩略图和压缩共享图；
- Realtime 按当前项目订阅，不订阅全局表；
- 保存时同步，不按输入字符同步；
- 断线恢复使用游标增量，不重复全量下载；
- 定期清理未加入任何项目且长期未使用的匿名账号；
- 监控 Storage、egress、Realtime 消息、数据库大小和 MAU；
- 正式发布前评估 Free 项目暂停、自动备份和容量风险，再决定是否升级 Pro。

## 16. 错误处理

- 无效或过期邀请：显示原因，并允许请求家人重新分享；
- 匿名会话丢失：若未绑定 Apple，明确告知当前设备身份不可恢复，不猜测或合并身份；
- Apple 身份已存在：进入账户合并流程，展示将保留的项目关系；
- 照片上传失败：保留本地文件和重试入口；
- 数据同步失败：保留 outbox，不回滚用户已经看到的本地操作；
- RLS 拒绝：停止重试该操作，刷新成员关系并显示可理解的权限错误；
- 项目已归档：阻止普通编辑，提供重新开启入口；
- 本地迁移失败：保留原始 AsyncStorage 数据并提供重试，不进入半迁移状态。

## 17. 测试策略

### 单元测试

- 操作幂等；
- 箱子状态合并和显式回退；
- 最后修改合并；
- 软删除和恢复；
- 箱号分配；
- 游标增量应用；
- 通知去重；
- 图片上传状态机。

### 数据库与权限测试

- 非成员不能读取或修改项目表；
- 非成员不能读取照片；
- 匿名成员与 Apple 成员拥有同等项目权限；
- 邀请过期或撤销后不能加入；
- 重复接受邀请不创建重复成员；
- 重复提交 `operationId` 不产生重复副作用。

### 多设备集成测试

- 三个独立用户加入同一项目；
- 两台设备离线同时创建箱子；
- 两台设备同时修改相同备注；
- 一台设备推进箱子状态，另一台离线提交旧状态；
- 离线添加照片后恢复网络；
- App 被杀死后 outbox 能继续提交；
- Realtime 中断期间的变化通过游标完整补回；
- 匿名身份升级 Apple 后保持同一成员。

### iOS 验证

- Universal Link 冷启动和前台启动；
- Apple 登录成功、取消和失败；
- APNs 权限允许和拒绝；
- 弱网、飞行模式和网络切换；
- 后台上传及被系统终止后的恢复；
- 动态字体、VoiceOver 标签和关键触控目标。

## 18. 不在第一版范围

- 家庭聊天；
- 实时位置；
- 搬家公司或临时访客角色；
- 管理员审批和复杂权限；
- 在线状态、实时光标和共同编辑文本；
- Android 或 Web 客户端；
- 多个活跃项目的完整切换界面；
- 上传相机原始大图；
- 完整自建后端或自托管 Supabase。

## 19. 分阶段交付建议

### 阶段一：共享文字数据

完成匿名身份、项目成员、邀请、任务/箱子/物品/房间实体同步、离线 outbox、游标增量和 RLS。先验证三台设备在弱网下不会互相覆盖。

### 阶段二：照片与身份保护

加入照片压缩上传、私有 Storage 权限、本地缓存、Apple 身份升级和回收站。

### 阶段三：搬家当天协作

加入负责人、活动记录、关键推送、状态更正、项目归档和协作体验优化。
